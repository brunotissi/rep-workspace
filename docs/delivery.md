# Architecture, evidence and demo

## Architecture and business rules

The local React/TypeScript client handles search, sorting, filtering, pagination and selection. Express holds OAuth tokens in memory and uses the signed-in user's Salesforce REST authorization. The Pipeline queries owned open Opportunities, follows Salesforce continuation pages and batches Account names and role evidence. The selected Snapshot and write endpoints verify the matching owned open Opportunity. Snapshot supporting data is Account-scoped and limited to what Salesforce sharing and field access permit.

| Assessment                         | Inputs and precedence                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Account Health in Snapshot**     | Red for any visible overdue open Opportunity or confirmed stale activity (21 days or more). Amber for a close date from today through day seven, missing visible activity or Decision Maker coverage, or no visible open pipeline when no Red condition applies. Green requires recent activity, open pipeline, a nearest close more than seven days away, and visible Decision Maker coverage on open Opportunities. An unknown input is marked incomplete. If it leaves no established risk, the assessment is shown as **Not assessed**. |
| **Opportunity Health in Pipeline** | Red for an overdue Close Date, or a date from today through day seven with confirmed missing visible Decision Maker coverage. Amber for a near-term date or confirmed missing coverage without a Red condition. Green requires a later date and visible coverage. If unknown inputs leave no confirmed risk, the UI shows **Not assessed**.                                                                                                                                                                                                 |

A successful empty role query establishes that the user saw no Decision Maker. A failed or incomplete query leaves coverage unknown. Health explanations identify those cases separately. The reason filter always offers business reasons and offers exceptional reasons when present in the loaded data or retained as the current selection after a refresh. The workspace uses a UTC business day and date-only comparisons. Amount filters compare record amounts without FX normalization.

Next Best Actions are ranked by overdue date, stale or absent completed Account activity without an existing open workspace follow-up, then missing visible Decision Maker on the selected Opportunity. Required input is collected in the card. Salesforce capability and context checks precede writes, and unverified evidence can suppress a recommendation. A resolved selection can have zero suggestions.

## Performance and verification

Five cache-disabled Chrome loads of **1,080 live Salesforce Opportunities** measured Pipeline GET at **953 ms median / 1,529 ms maximum**. Forty-five local search, filter, sort and page interactions measured **33.4 ms estimated median / 53.2 ms maximum**, with **zero additional Pipeline requests**. The localhost harness used the production UI and Express routes, real Salesforce REST reads, and controlled local session setup. It excluded OAuth sign-in time. Interaction timing used two animation-frame callbacks as a paint approximation. The baseline predates the latest minor UI refinements. Upstream Salesforce I/O dominated the GET. Batched evidence reads, local operations and 50-row pages limit request and render work.

- **Live Salesforce:** Separate admin and restricted OAuth sessions verified full owned scope, permission degradation and Account context. The three live browser writes were independently read back in Salesforce. Fresh seed Apply and Verify ran in a disposable org, with independent inventory and a duplicate-free repeat.
- **Simulated failures:** The **69 passing application tests** cover success, empty states, permission failures, validation, expiry, quota and partial reads, ambiguous writes and optimistic rollback. Isolated HTTP and Chrome checks supplied additional boundary and UI evidence using mocked transport. Offline PowerShell seed verification separately exercised a partial batch failure and resume.
- **Accessibility:** Owner keyboard walkthroughs used desktop and narrow Chrome views. NVDA 2026.3.1 with Chrome on Windows verified landmarks, tables, disclosures, permission text, validation and toast announcements. Owner retests included 200% browser zoom and narrow widths. Isolated Chrome added contrast, grayscale, reduced-motion, focus and obstruction checks. These results describe the tested environment.
- **Write recovery:** The server checks the previous Close Date and suppresses overlapping same-target actions in one process. The UI disables repeat submission while pending and refreshes after an uncertain outcome or conflict. A tested Close Date replay was a no-op. Task and Contact Role operations carry no universal exactly-once guarantee.

## Known limitations and optional scope

The workspace is desktop-first with a horizontally scrollable Pipeline table on narrow screens. Narrow notifications use space above the actions while displayed. UTC stays the reference date for the fetched data. Scheduled midnight refresh and user-local business dates are deferred. Opportunity selection from Snapshot is intentionally deferred. Rule thresholds are source constants. An administrator rule editor, workspace audit trail, automatic write retries and a pre-build Figma prototype are outside the delivered scope.
